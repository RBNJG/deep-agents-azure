# B04 — Prueba temprana de Azure e identidades

**Objetivo:** Resolver riesgos de UAMI, PostgreSQL, Entra y retirada antes de completar la plataforma.

**Dependencias de entrada:** B03. Comprobar sus handoffs y el código.

## Contexto para el agente

Esta es una prueba acotada y temporal. Todavía no requiere la UI ni el worker definitivo. Las piezas Terraform útiles se reutilizan; las apps de eco son identificables como pruebas. Si faltan credenciales, dejar preflight y plan listos y continuar con B05 local.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** infra/modules/, infra/environments/spike/, scripts/azure_preflight* y tests/cloud_smoke/.

**Fuera de alcance:** Entorno permanente, servicios de pago adicionales y afirmar que mocks validan UAMIs.

## B04.1 — Crear preflight e IaC mínimo

**Modo:** LOCAL. **Depende de:** B03.4.

**Implementar:** Definir suscripción/tenant/environment_id, variables sin secretos, state protegido, nombres/tags y límites de recursos. Modelar PostgreSQL pequeño, Storage, Key Vault, UAMIs y cómputo mínimo de prueba. Preparar plan/destroy desde el inicio.

**Entregable:** Módulos Terraform, validación y checklist ejecutable de prerrequisitos.

**Aceptación:** terraform validate pasa; el preflight detecta permisos/configuración ausentes antes de crear recursos. Recursos y permisos tienen alcance de demo definido.

**Entrega al siguiente agente:** `docs/handoffs/B04.1.md`, usando la plantilla común.

## B04.2 — Probar acceso UAMI a datos

**Modo:** AZURE. **Depende de:** B04.1.

**Implementar:** Aplicar el entorno de prueba configurado. Inicializar roles SQL ligados a los principales reales y GRANT acotados; un contenedor/Job usa tokens para PostgreSQL, Blob y lectura de un secreto de prueba de Key Vault. Probar acceso permitido y denegado y nuevas conexiones del pool.

**Entregable:** Script de smoke cloud y registro de IDs/roles sin secretos.

**Aceptación:** La conexión funciona sin contraseña permanente ni storage key; el principal sin permiso recibe denegación, también en Key Vault. No imprimir el secreto. La prueba local no sustituye esta evidencia.

**Entrega al siguiente agente:** `docs/handoffs/B04.2.md`, usando la plantilla común.

## B04.3 — Probar identidad de usuario y servicio

**Modo:** AZURE. **Depende de:** B04.2.

**Implementar:** Registrar cliente/API/MCP de prueba con scopes y app roles. Verificar API a MCP por OBO y UAMI a MCP app-only. Elegir federación UAMI como credencial confidencial si está comprobada; documentar certificado como alternativa si procede.

**Entregable:** ADR de autenticación, Terraform Entra y pruebas con endpoints mínimos.

**Aceptación:** MCP distingue usuario de servicio y rechaza audiencia equivocada. Un token app-only no pasa como usuario. Consentimientos y requisitos del tenant quedan documentados.

**Entrega al siguiente agente:** `docs/handoffs/B04.3.md`, usando la plantilla común.

## B04.4 — Retirar la prueba y medir

**Modo:** AZURE. **Depende de:** B04.3.

**Implementar:** Destruir con el state de la prueba, inventariar restos dentro y fuera del resource group y manejar Key Vault soft-delete sin purgas ajenas. Registrar duración, recursos y costes disponibles, indicando su posible retraso.

**Entregable:** Teardown inicial y reporte de viabilidad/coste.

**Aceptación:** No quedan workloads activos de la prueba ni se elimina el state con recursos pendientes. Si un recurso no se borra, hay instrucciones concretas para reintentar.

**Entrega al siguiente agente:** `docs/handoffs/B04.4.md`, usando la plantilla común.

## Puerta de salida del bloque

Hay evidencia real de conexión UAMI a PostgreSQL/Storage, tokens correctos para MCP y retirada del entorno de prueba, o estado BLOCKED_EXTERNAL explícito.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
