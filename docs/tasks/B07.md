# B07 — Interfaz mínima para enseñar el proceso

**Objetivo:** Permitir que solicitante y aprobador completen la demo sin CLI.

**Dependencias de entrada:** B05. Comprobar sus handoffs y el código.

## Contexto para el agente

La UI representa los estados existentes y no inventa una segunda máquina de estados. Desarrollar inicialmente con identidad local, y conectar Entra mediante la interfaz de B06 antes de cerrar B08. Priorizar claridad de acciones sobre diseño decorativo.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** apps/api/web/ o frontend acotado, clientes API y tests/ui/.

**Fuera de alcance:** Dashboard complejo, diseñador de workflows, SSR y notificaciones de pago.

## B07.1 — Crear navegación y vista de ejecución

**Modo:** LOCAL. **Depende de:** B05.4.

**Implementar:** Implementar entrada, selector de proyecto, chat/petición y lista de runs. Mostrar plan y eventos del servidor mediante polling; conservar run_id en URL y permitir volver tras recargar.

**Entregable:** UI básica y cliente API tipado.

**Aceptación:** Una recarga recupera estado y no inicia otra tarea. Los errores de red se distinguen de una tarea fallida.

**Entrega al siguiente agente:** `docs/handoffs/B07.1.md`, usando la plantilla común.

## B07.2 — Renderizar preguntas y aprobaciones

**Modo:** LOCAL. **Depende de:** B07.1.

**Implementar:** Mostrar formularios según schema y revisión de argumentos/destino/importe. Separar aprobación de herramienta de aprobación de compra. Añadir bandeja del aprobador sin exponer mensajes privados no necesarios.

**Entregable:** Pantallas de acciones pendientes y decisiones.

**Aceptación:** Doble clic no duplica la decisión; versión vieja muestra conflicto. Rechazar detiene la acción y el modelo no puede sustituir esa decisión.

**Entrega al siguiente agente:** `docs/handoffs/B07.2.md`, usando la plantilla común.

## B07.3 — Mostrar documentos, evidencias y bandeja demo

**Modo:** LOCAL. **Depende de:** B07.2.

**Implementar:** Crear vista de ofertas, comparación, enlaces autorizados a evidencias, descarga y mensajes de proveedores simulados. Etiquetar datos sintéticos y distinguir simulación de envío real.

**Entregable:** UI del expediente de compra y llegada de respuesta preparada.

**Aceptación:** Se puede localizar de qué oferta salió un importe y completar la espera de proveedor. Ningún enlace expone un artefacto de otro proyecto.

**Entrega al siguiente agente:** `docs/handoffs/B07.3.md`, usando la plantilla común.

## B07.4 — Cerrar recorrido de navegador

**Modo:** LOCAL. **Depende de:** B07.3.

**Implementar:** Ejecutar prueba UI del caso feliz y rechazo, reconexión, cancelación y estado WAITING_AUTH con proveedor de desarrollo. Asegurar accesibilidad básica de formularios y navegación por teclado. Preparar puntos de integración Entra.

**Entregable:** Test de navegador y guion de demo local.

**Aceptación:** Dos roles completan el proceso y las decisiones finales coinciden con PostgreSQL. No se declara login real probado hasta integrar B06/B08.

**Entrega al siguiente agente:** `docs/handoffs/B07.4.md`, usando la plantilla común.

## Puerta de salida del bloque

Desde el navegador se crea una tarea, se responde, se revisa una compra, se consulta progreso y se descarga un resultado.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
