# B06 — Autenticación y autorización reales

**Objetivo:** Sustituir la identidad de desarrollo por Entra sin modificar las reglas de negocio.

**Dependencias de entrada:** B04, B05. Comprobar sus handoffs y el código.

## Contexto para el agente

B04 ya probó los flujos; ahora se integran en API, worker y MCP reales. Recrear un entorno temporal con su IaC para las pruebas y retirarlo al terminar la sesión; no depender de recursos destruidos en B04. Las pruebas negativas importan tanto como el camino correcto. No basta con ocultar botones o herramientas.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** packages/platform/identity/, apps/api/auth/, apps/mcp_server/auth/, infra identity modules y tests/security/.

**Fuera de alcance:** Multitenancy comercial, Graph y un almacén duradero de refresh tokens.

## B06.1 — Integrar login y validación de tokens

**Modo:** LOCAL + AZURE. **Depende de:** B04.4, B05.4.

**Implementar:** Implementar authorization code/PKCE para el cliente, access tokens para API, validación criptográfica de issuer/audience/expiración y tenant admitido. Resolver memberships desde el servidor; proteger endpoints humanos.

**Entregable:** Autenticación real y configuración por entorno.

**Aceptación:** Tokens expirados, de otra audiencia o tenant no autorizado fallan. Un ID token no autoriza la API. No se guardan credenciales en eventos/checkpoints.

**Entrega al siguiente agente:** `docs/handoffs/B06.1.md`, usando la plantilla común.

## B06.2 — Integrar la ruta de servicio

**Modo:** AZURE. **Depende de:** B06.1.

**Implementar:** Asignar UAMIs por workload, app roles MCP y roles de datos. Restringir cada servicio a sus tablas/contenedores. El contexto del run/proyecto que recibe MCP es verificado y no una cabecera libre del modelo.

**Entregable:** Credenciales Azure, SQL grants y política app-only.

**Aceptación:** Worker no escribe aprobaciones ni ejecuta tools delegadas; MCP solo guarda en destinos autorizados. Se comprueba una llamada real por UAMI.

**Entrega al siguiente agente:** `docs/handoffs/B06.2.md`, usando la plantilla común.

## B06.3 — Integrar OBO y espera de autenticación

**Modo:** AZURE. **Depende de:** B06.2.

**Implementar:** Adaptar el puente B05 a API→MCP OBO. No serializar bearer tokens. Si falta sesión/consentimiento, mantener la espera y guiar la reconexión. Reautorizar la acción al reanudar y conservar el propietario original.

**Entregable:** Flujo delegado y manejo de AUTH_REQUIRED.

**Aceptación:** Una acción delegada usa el usuario correcto; token ausente/expirado no activa fallback de servicio. Volver a autenticar permite continuar sin repetir efectos.

**Entrega al siguiente agente:** `docs/handoffs/B06.3.md`, usando la plantilla común.

## B06.4 — Cerrar la matriz de permisos

**Modo:** LOCAL + AZURE. **Depende de:** B06.3.

**Implementar:** Probar requester, approver, usuario ajeno y workload. Intentar acceso cruzado, autoaprobación, replay, cambio de importe tras aprobar y ejecución directa de tool sin aprobación. Probar denegación al retirar membresía de negocio.

**Entregable:** Matriz de autorización y suite negativa reproducible.

**Aceptación:** Cero accesos indebidos en esos casos. Los límites de propagación de permisos externos se documentan; no se afirma revocación Azure instantánea.

**Entrega al siguiente agente:** `docs/handoffs/B06.4.md`, usando la plantilla común.

## Puerta de salida del bloque

Usuario, aprobador y servicio tienen permisos distintos comprobados en Azure, y el perfil cloud rechaza configuración de desarrollo.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
