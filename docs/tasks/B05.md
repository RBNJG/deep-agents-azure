# B05 — API y ejecución asíncrona resistente

**Objetivo:** Separar peticiones HTTP de ejecución y reanudar trabajos de manera fiable.

**Dependencias de entrada:** B03. Comprobar sus handoffs y el código.

## Contexto para el agente

El recorrido CLI de B03 es la referencia. El worker procesa segmentos, no duerme durante una espera humana. Guardar estado de negocio y outbox con transacciones propias; no asumir atomicidad con el saver de LangGraph.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** apps/api/, apps/worker/, packages/platform/queue/, control migrations y tests/recovery/.

**Fuera de alcance:** Diseño visual, Graph y perfeccionamiento de prompts.

## B05.1 — Implementar API de runs y control

**Modo:** LOCAL. **Depende de:** B03.4.

**Implementar:** Crear endpoints definidos, autorización de propietario con el proveedor de desarrollo, versionado optimista y persistencia de estado/eventos. Devolver 202 al crear trabajo. Separar peticiones de compra de conversaciones privadas.

**Entregable:** API, OpenAPI y repositorios de control.

**Aceptación:** No se bloquea HTTP hasta terminar el agente. Dos proyectos no ven runs ajenos; versiones obsoletas de respuestas/decisiones se rechazan.

**Entrega al siguiente agente:** `docs/handoffs/B05.1.md`, usando la plantilla común.

## B05.2 — Implementar outbox y consumidor de cola

**Modo:** LOCAL. **Depende de:** B05.1.

**Implementar:** Persistir comandos y outbox; despachar a Storage Queue/Azurite y consumir con un único lease por hilo. Renovar invisibilidad mientras corre, confirmar después del checkpoint/estado duradero y finalizar al interrumpirse.

**Entregable:** Dispatcher, entrypoint de worker y mensaje ExecutionCommand versionado.

**Aceptación:** Duplicar mensajes no ejecuta dos segmentos simultáneos del mismo hilo. Caer entre guardar y encolar se recupera sin perder el run.

**Entrega al siguiente agente:** `docs/handoffs/B05.2.md`, usando la plantilla común.

## B05.3 — Conectar respuestas y decisiones humanas

**Modo:** LOCAL. **Depende de:** B05.2.

**Implementar:** Implementar el puente de llamadas delegadas y validación de respuestas. API ejecuta la herramienta usando argumentos persistidos y guarda resultado confiable. Una decisión de compra de otro aprobador emite evento de dominio sin cambiar owner_id del run.

**Entregable:** Rutas de respuesta/decisión/llamada delegada y reconciliación.

**Aceptación:** Cerrar el cliente deja una espera persistida. Un usuario no puede inyectar un resultado MCP. El aprobador decide una compra sin obtener acceso general al chat del solicitante.

**Entrega al siguiente agente:** `docs/handoffs/B05.3.md`, usando la plantilla común.

## B05.4 — Probar fallos, reintentos y cancelación

**Modo:** LOCAL. **Depende de:** B05.3.

**Implementar:** Implementar reintentos acotados con backoff, cola de fallidos de la aplicación, cancelación cooperativa y reconciliador de proyecciones. Inyectar caída antes/después de efectos, expiración de lease y doble clic.

**Entregable:** Pruebas de recuperación y guía de operación local.

**Aceptación:** Cada escenario termina o queda recuperable con causa visible. Se conserva un único efecto y una cancelación no inicia nuevas acciones; no se promete revertir una acción externa ya confirmada.

**Entrega al siguiente agente:** `docs/handoffs/B05.4.md`, usando la plantilla común.

## Puerta de salida del bloque

API devuelve un run, el worker avanza y se interrumpe; respuestas y eventos reanudan una vez, incluso tras fallos y mensajes duplicados.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
