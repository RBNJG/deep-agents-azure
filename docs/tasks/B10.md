# B10 — Evaluaciones, Langfuse y mejora controlada

**Objetivo:** Demostrar con resultados reproducibles qué funciona y qué mejora.

**Dependencias de entrada:** B08, B09. Comprobar sus handoffs y el código.

## Contexto para el agente

Los eventos y diez casos existen desde B01/B03; esta fase los amplía. El dataset reservado no se utiliza para redactar la skill candidata. Seguridad y cálculos se validan con código, no con un juez LLM.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** evals/, packages/platform/telemetry/, CI eval manual, reports y tests/security,recovery/.

**Fuera de alcance:** Langfuse autoalojado, evaluación cara por cada commit y publicación automática por una sola métrica.

## B10.1 — Conectar observabilidad completa

**Modo:** LOCAL + LLM + AZURE. **Depende de:** B08.4, B09.4.

**Implementar:** Integrar Langfuse según versiones fijadas y correlacionar API, segmentos, subagentes y tools. Registrar costes configurados, versión y tipo de identidad; redactar secretos/contenido sensible. Vaciar spans al terminar Jobs.

**Entregable:** Tracing configurable, métricas y pruebas de redacción.

**Aceptación:** Una ejecución con pausa y reanudación se sigue por IDs; no falta el final del Job. La caída del exportador no ejecuta acciones duplicadas ni expone datos.

**Entrega al siguiente agente:** `docs/handoffs/B10.1.md`, usando la plantilla común.

## B10.2 — Construir harness de evaluación

**Modo:** LOCAL + LLM. **Depende de:** B10.1.

**Implementar:** Ampliar a 30–50 casos separados en dominio, permisos, recuperación y calidad agéntica. Congelar fixtures/reloj y ejecutar varios intentos en casos variables. Registrar denominadores, versión y costes, incluidos fallos.

**Entregable:** Runner y reporte JSON/Markdown con criterios explícitos.

**Aceptación:** Totales y autorización se evalúan determinísticamente. El informe distingue mocks, modelo real y Azure; no omite ejecuciones fallidas del porcentaje.

**Entrega al siguiente agente:** `docs/handoffs/B10.2.md`, usando la plantilla común.

## B10.3 — Evaluar y promover una skill

**Modo:** LOCAL + LLM. **Depende de:** B10.2.

**Implementar:** Comparar v1 y candidata con misma configuración y casos de validación; reservar holdout. Revisar calidad, regresiones y coste. Promoción por mantenedor mediante commit/release y rollback; conservar bundle anterior para runs pendientes.

**Entregable:** Experimento, decisión y proceso de publicación de skills.

**Aceptación:** Solo se afirma mejora si las métricas la apoyan. Una regresión de autorización impide promoción; volver a la versión anterior está probado.

**Entrega al siguiente agente:** `docs/handoffs/B10.3.md`, usando la plantilla común.

## B10.4 — Cerrar fiabilidad y límites de gasto

**Modo:** LOCAL + AZURE. **Depende de:** B10.3.

**Implementar:** Ejecutar matriz final de fallos: mensajes duplicados, contenedor terminado, token expirado, proveedor lento, aprobación alterada y presupuesto agotado. Verificar quotas, cola fallida, cancelación y recuperación documentada.

**Entregable:** Informe de aceptación técnica y runbooks breves.

**Aceptación:** Cero efectos no autorizados en la batería y costes/iteraciones limitados. Los fallos se hacen visibles; no hay loops silenciosos ni promesas de exactly-once.

**Entrega al siguiente agente:** `docs/handoffs/B10.4.md`, usando la plantilla común.

## Puerta de salida del bloque

Existe un reporte de 30–50 casos, trazas correlacionadas y comparación baseline/candidata con decisión de promoción justificada.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
