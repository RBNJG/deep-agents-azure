# B12 — Extensión opcional de Microsoft Graph

**Objetivo:** Añadir correo/documentos externos si la cuenta disponible permite hacerlo sin coste desproporcionado.

**Dependencias de entrada:** B11. Comprobar sus handoffs y el código.

## Contexto para el agente

El producto principal ya funciona con datos sintéticos y Entra. El tipo de cuenta y licencias determinan las APIs y el flujo OAuth; no se asume que una cuenta personal permite la misma cadena OBO de un tenant de trabajo.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** packages/platform/graph/, herramientas MCP opcionales, configuración Entra y tests/integration_graph/.

**Fuera de alcance:** Licencias contratadas automáticamente, pagos, acceso amplio al tenant y datos reales incluidos en Git.

## B12.1 — Verificar cuenta, APIs y consentimiento

**Modo:** LOCAL. **Depende de:** B11.4.

**Implementar:** Identificar cuenta personal o de trabajo, APIs requeridas, scopes mínimos y permisos administrativos disponibles. Hacer ADR de flujo OAuth y presupuesto. No comprar una suscripción para salvar una incompatibilidad sin decisión del usuario.

**Entregable:** Matriz de capacidades y prerrequisitos de Graph.

**Aceptación:** Las operaciones elegidas tienen soporte confirmado para esa cuenta; las no disponibles se excluyen explícitamente.

**Entrega al siguiente agente:** `docs/handoffs/B12.1.md`, usando la plantilla común.

## B12.2 — Integrar lectura de ofertas

**Modo:** LLM + EXTERNO. **Depende de:** B12.1.

**Implementar:** Añadir búsqueda/lectura acotada de correo o OneDrive y descarga con identidad del usuario. Reutilizar ingestión y evidencias B02; limitar tamaño, tipos y ámbito. Mantener perfil demo independiente.

**Entregable:** Tools Graph de lectura y prueba con datos de ensayo en una cuenta autorizada.

**Aceptación:** Solo se recupera contenido al que el usuario tiene acceso. Expiración/consentimiento pendiente no produce fallback app-only.

**Entrega al siguiente agente:** `docs/handoffs/B12.2.md`, usando la plantilla común.

## B12.3 — Integrar envío aprobado y respuestas

**Modo:** EXTERNO. **Depende de:** B12.2.

**Implementar:** Crear borrador/revisión y envío de aclaraciones, con destinatario y contenido exactos. Registrar identificadores del proveedor y diseñar reconciliación para timeouts de resultado incierto; no reenviar a ciegas. Incluir respuesta mediante polling bajo demanda antes de webhooks.

**Entregable:** Ciclo de aclaración real y recuperación de resultados inciertos.

**Aceptación:** Se envía una sola vez cuando puede verificarse; ante incertidumbre se pausa para reconciliar. Las respuestas se vinculan al expediente correcto y un rechazo no envía nada.

**Entrega al siguiente agente:** `docs/handoffs/B12.3.md`, usando la plantilla común.

## B12.4 — Evaluar y retirar permisos de prueba

**Modo:** EXTERNO. **Depende de:** B12.3.

**Implementar:** Repetir casos de autorización, token expirado y prompt injection con documentos externos de ensayo. Documentar consentimiento y retirada de registros/artefactos creados, sin borrar contenido ajeno.

**Entregable:** Reporte y guía de activación/desactivación del perfil Graph.

**Aceptación:** El perfil básico sigue funcionando sin Graph; desactivar integración no impide cargar el dataset ni retirar la demo Azure.

**Entrega al siguiente agente:** `docs/handoffs/B12.4.md`, usando la plantilla común.

## Puerta de salida del bloque

La integración real añade valor y supera pruebas de permiso y aprobación, o queda desactivada con la razón documentada sin bloquear el proyecto.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
