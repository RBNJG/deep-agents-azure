# B01 — PostgreSQL local y dataset reproducible

**Objetivo:** Disponer de datos de compras y documentos coherentes, recargables y baratos.

**Dependencias de entrada:** B00. Comprobar sus handoffs y el código.

## Contexto para el agente

El seed es la fuente de una demo nueva. Los IDs de dominio son estables; las identidades Entra se vinculan después. Local y Azure usan las mismas migraciones y contratos de repositorio.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** migrations/, packages/platform/db/, demo/datasets/v1/, scripts/seed* y compose.

**Fuera de alcance:** Decisiones del LLM, autenticación Azure y dependencias de Microsoft 365.

## B01.1 — Crear persistencia y migraciones

**Modo:** LOCAL. **Depende de:** B00.4.

**Implementar:** Levantar PostgreSQL y Azurite. Crear esquemas/roles locales y migraciones para proyectos, miembros, proveedores, ofertas, inventario, solicitudes, control y auditoría. No dar al worker escritura sobre aprobaciones.

**Entregable:** Alembic y repositorios mínimos con transacciones explícitas.

**Aceptación:** Migrar desde vacío funciona; restricciones impiden referencias cruzadas incoherentes y el rol worker no escribe decisiones humanas.

**Entrega al siguiente agente:** `docs/handoffs/B01.1.md`, usando la plantilla común.

## B01.2 — Generar dataset y documentos

**Modo:** LOCAL. **Depende de:** B01.1.

**Implementar:** Crear seis proveedores, doce productos, dos proyectos y ofertas con transporte ausente, vigencia y distintos requisitos. Generar PDF/XLSX legibles con datos idénticos a la fuente estructurada. Definir fecha base y manifiesto/hash.

**Entregable:** Fixtures, generadores deterministas y documentos sintéticos.

**Aceptación:** Regenerar con misma semilla produce datos equivalentes; las cifras de documentos coinciden con fixtures y no aparecen datos privados.

**Entrega al siguiente agente:** `docs/handoffs/B01.2.md`, usando la plantilla común.

## B01.3 — Implementar seed idempotente

**Modo:** LOCAL. **Depende de:** B01.2.

**Implementar:** Cargar filas mediante transacciones/upserts y documentos mediante claves estables. Separar seed de reset; este último comprueba environment_id y detiene/cancela runs de demo previos. Añadir mapeo configurable de personas a identidades.

**Entregable:** Comandos seed, seed-check y reset acotado al entorno.

**Aceptación:** Ejecutar seed dos veces mantiene conteos y relaciones. Un environment_id incorrecto impide reset. Faltan identidades reales: se informa, no se inventan oids.

**Entrega al siguiente agente:** `docs/handoffs/B01.3.md`, usando la plantilla común.

## B01.4 — Definir escenarios y resultados esperados

**Modo:** LOCAL. **Depende de:** B01.3.

**Implementar:** Preparar diez casos con entradas, hechos verificables, acciones permitidas y resultado esperado. Incluir aclaración, rechazo, acceso ajeno, oferta vencida y duplicación. Separar casos de demo y evaluación reservada.

**Entregable:** demo/scenarios/ y evals/datasets/baseline con fecha congelada.

**Aceptación:** Cada caso puede resolverse manualmente con las evidencias disponibles; falta de transporte se representa como desconocida y nunca como coste cero.

**Entrega al siguiente agente:** `docs/handoffs/B01.4.md`, usando la plantilla común.

## Puerta de salida del bloque

Dos cargas consecutivas producen el mismo dataset sin duplicados y una BD vacía se reconstruye con migraciones y seed.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
