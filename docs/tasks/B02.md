# B02 — Dominio de compras y servidor MCP

**Objetivo:** Exponer acciones reales y controladas antes de conectarlas al agente.

**Dependencias de entrada:** B01. Comprobar sus handoffs y el código.

## Contexto para el agente

El LLM decide cómo avanzar, pero importes, transiciones de compra y permisos se resuelven con código. Un cliente MCP de prueba debe poder completar el proceso sin LLM.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** packages/domain/, packages/platform/artifacts/, apps/mcp_server/ y tests/domain,mcp/.

**Fuera de alcance:** Aprobación autónoma, SQL/shell arbitrarios, pagos y correo externo.

## B02.1 — Implementar reglas y cálculos

**Modo:** LOCAL. **Depende de:** B01.4.

**Implementar:** Crear comparación normalizada con Decimal, EUR, cantidad, impuestos, descuentos y transporte; definir orden/redondeo. Implementar estados y versiones de solicitud, membresía y separación de solicitante/aprobador.

**Entregable:** Servicios de dominio sin dependencias del LLM y tests con fixtures B01.

**Aceptación:** Totales coinciden con cálculos de referencia. No se recomienda como plenamente comparable una oferta incompleta sin señalarlo.

**Entrega al siguiente agente:** `docs/handoffs/B02.1.md`, usando la plantilla común.

## B02.2 — Ingerir documentos y producir evidencias

**Modo:** LOCAL. **Depende de:** B02.1.

**Implementar:** Soportar PDF con texto y XLSX del dataset, límites de tamaño y extracción con página/celda. Guardar fuente/hash y campos ambiguos; OCR queda fuera. Generar comparativa estructurada y reporte Markdown/HTML.

**Entregable:** Adaptadores de extracción, EvidenceRef y guardado de artefactos.

**Aceptación:** Cada cifra importante se vincula a una fuente; PDF ilegible devuelve resultado explícito y no datos fabricados. HTML se sirve de forma segura.

**Entrega al siguiente agente:** `docs/handoffs/B02.2.md`, usando la plantilla común.

## B02.3 — Publicar herramientas MCP y políticas

**Modo:** LOCAL. **Depende de:** B02.2.

**Implementar:** Implementar Streamable HTTP y las herramientas de CONTRACTS.md sobre dominio. Introducir ActorContext a través de un verificador local explícito; el perfil cloud no permite ese verificador. Aplicar autorización en todas las llamadas, también directas.

**Entregable:** Servidor MCP, catálogo de herramientas y policy table.

**Aceptación:** list_tools y call_tool funcionan sobre HTTP. Token/contexto incorrecto y proyecto ajeno se deniegan. approve_purchase_request no está en el catálogo del LLM.

**Entrega al siguiente agente:** `docs/handoffs/B02.3.md`, usando la plantilla común.

## B02.4 — Añadir idempotencia y diario de efectos

**Modo:** LOCAL. **Depende de:** B02.3.

**Implementar:** Registrar action_id y payload_hash. Coordinar escrituras SQL con transacciones y artefactos con publicación idempotente/reconciliación. Crear bandeja demo para aclaraciones y el comando humano de decisión.

**Entregable:** Ledger de efectos y pruebas de replay y conflictos.

**Aceptación:** Repetir una solicitud/publicación devuelve el resultado previo; cambiar payload con misma clave falla. Rechazar una compra impide submit_purchase_request.

**Entrega al siguiente agente:** `docs/handoffs/B02.4.md`, usando la plantilla común.

## Puerta de salida del bloque

Un cliente MCP consulta ofertas, genera un borrador y crea una solicitud; acciones no autorizadas y duplicadas se manejan correctamente.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
