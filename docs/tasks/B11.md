# B11 — Entrega del portfolio y reproducción

**Objetivo:** Convertir el trabajo en una demostración que otra persona pueda entender y reproducir.

**Dependencias de entrada:** B10. Comprobar sus handoffs y el código.

## Contexto para el agente

El código y resultados existen; este bloque documenta hechos comprobados. La demo pública puede ser vídeo y modo local, evitando una suscripción encendida permanentemente.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** README, docs/, demo scripts, releases y workflow CI.

**Fuera de alcance:** Métricas inventadas, incorporar funciones nuevas y mantener Azure siempre disponible.

## B11.1 — Redactar documentación y ADRs finales

**Modo:** LOCAL. **Depende de:** B10.4.

**Implementar:** Explicar problema, arquitectura, contratos, permisos, coste observado y límites. Documentar local/demo-up/demo-down, prerequisitos y troubleshooting. Conservar la diferencia entre seed limpio y restauración de sesión.

**Entregable:** README y ADRs actualizados a lo implementado.

**Aceptación:** Los comandos documentados existen y funcionan; versiones y capturas coinciden con el código entregado.

**Entrega al siguiente agente:** `docs/handoffs/B11.1.md`, usando la plantilla común.

## B11.2 — Preparar demo y evidencia

**Modo:** LOCAL + AZURE. **Depende de:** B11.1.

**Implementar:** Crear guion breve: ofertas, dato ausente, pausa, reinicio, aprobación, solicitud, denegación y skill. Grabar datos sintéticos y ocultar IDs/secretos no necesarios. Adjuntar reporte de evaluación y segundo ciclo de despliegue.

**Entregable:** Vídeo/capturas y evidencias publicables.

**Aceptación:** Queda visible qué es real y qué es fixture. No se presenta una bandeja simulada como envío Outlook ni una prueba local como autorización Azure.

**Entrega al siguiente agente:** `docs/handoffs/B11.2.md`, usando la plantilla común.

## B11.3 — Publicar paquete reproducible

**Modo:** LOCAL. **Depende de:** B11.2.

**Implementar:** Preparar release de código, imágenes por digest, dataset con checksums y ejemplo de configuración. Revisar licencia con el mantenedor y escaneo de secretos. Configurar CI económica y tareas con modelos solo bajo ejecución controlada.

**Entregable:** Release y checklist de reproducibilidad, sin states ni dumps privados.

**Aceptación:** Una máquina limpia instala y carga el dataset; el paquete no contiene credenciales ni depende de un directorio local del autor.

**Entrega al siguiente agente:** `docs/handoffs/B11.3.md`, usando la plantilla común.

## B11.4 — Realizar revisión de cierre

**Modo:** LOCAL + AZURE. **Depende de:** B11.3.

**Implementar:** Revisar criterios de todos los bloques y handoffs. Ejecutar el recorrido final y comprobar retirada. Abrir issues de limitaciones reales y separar ampliaciones opcionales de requisitos incumplidos.

**Entregable:** Matriz requisito→implementación→evidencia y backlog posterior.

**Aceptación:** Cada capacidad prometida tiene prueba o limitación explícita. No quedan recursos facturables propios de la última demo sin identificar.

**Entrega al siguiente agente:** `docs/handoffs/B11.4.md`, usando la plantilla común.

## Puerta de salida del bloque

Un checkout limpio y una persona que no desarrolló el último bloque pueden reproducir el caso y su retirada siguiendo la documentación.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
