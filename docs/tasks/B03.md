# B03 — Primer agente con pausa duradera

**Objetivo:** Completar el primer recorrido de compra mediante Deep Agents y PostgreSQL.

**Dependencias de entrada:** B02. Comprobar sus handoffs y el código.

## Contexto para el agente

Empezar con un único agente principal y una skill. El entrypoint puede ser CLI; no hace falta esperar a la web. Integrar checkpointer y store reales en PostgreSQL, no un saver en memoria para la prueba de reinicio.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** packages/agents/, skills/compare-quotes/, scripts/run_local_agent* y tests/agent/.

**Fuera de alcance:** Multiagente amplio, cloud completo, aprendizaje automático de skills y frontend.

## B03.1 — Construir el agente y sus límites

**Modo:** LOCAL + LLM. **Depende de:** B02.4.

**Implementar:** Configurar create_deep_agent según la versión fijada, modelo intercambiable, herramientas MCP, planificación y límites de pasos/llamadas/tokens. Conservar observaciones/evidencias sin permitir instrucciones de documentos como permisos.

**Entregable:** Factory del agente, configuración de modelo y primer procedimiento.

**Aceptación:** Con modelo simulado recorre el caso determinista; una ejecución con modelo real, si está configurado, demuestra tool calling y se registra por separado con consumo.

**Entrega al siguiente agente:** `docs/handoffs/B03.1.md`, usando la plantilla común.

## B03.2 — Conectar saver, store y workspace

**Modo:** LOCAL. **Depende de:** B03.1.

**Implementar:** Inicializar saver/store PostgreSQL mediante su paso de setup y usar thread_id estable. Configurar rutas de workspace, memoria y skills; conservar archivos grandes en Blob/Azurite. Separar namespaces de usuarios/proyectos.

**Entregable:** Adaptadores de persistencia y configuración del filesystem virtual.

**Aceptación:** Dos hilos reanudan su propio estado; otro usuario no puede recuperar memoria ajena. Los ficheros no crecen sin límite dentro del checkpoint.

**Entrega al siguiente agente:** `docs/handoffs/B03.2.md`, usando la plantilla común.

## B03.3 — Implementar preguntas y aprobaciones

**Modo:** LOCAL. **Depende de:** B03.2.

**Implementar:** Crear herramientas de pregunta tipada y acción pendiente con interrupt/resume. La respuesta y decisión entran mediante un adaptador humano de CLI, identificado como desarrollo. Validar hashes/versiones y respetar rechazo/edición.

**Entregable:** Flujo local de HITL con payloads persistentes.

**Aceptación:** Mientras falta presupuesto no continúa la acción dependiente. Tras reinicio, el mismo interrupt acepta una respuesta válida; una aprobación de otra acción no sirve.

**Entrega al siguiente agente:** `docs/handoffs/B03.3.md`, usando la plantilla común.

## B03.4 — Añadir traza mínima y caso completo

**Modo:** LOCAL + LLM. **Depende de:** B03.3.

**Implementar:** Emitir eventos estructurados correlacionados por run, segmento, tool_call e identidad. Usar precios configurables para estimar coste y ocultar tokens. Automatizar la demo local con un modelo simulado y documentar ejecución real.

**Entregable:** Primer smoke end-to-end y reporte baseline de diez casos cuando aplique.

**Aceptación:** Puede reconstruirse el recorrido desde eventos. No se confunden éxito con modelo simulado y éxito real; se conserva evidencia del reinicio y de ausencia de duplicados.

**Entrega al siguiente agente:** `docs/handoffs/B03.4.md`, usando la plantilla común.

Pedir aclaración, terminar el proceso, arrancarlo de nuevo y continuar el mismo hilo sin repetir el efecto.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
