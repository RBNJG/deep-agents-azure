# B08 — Demo Azure desplegable y eliminable

**Objetivo:** Automatizar el ciclo completo con los servicios reales y el dataset.

**Dependencias de entrada:** B06, B07. Comprobar sus handoffs y el código.

## Contexto para el agente

Reutilizar Terraform de B04 y la aplicación de B05–B07. IaC, migraciones y seed son pasos distintos coordinados por scripts. El state local es el perfil por defecto para no conservar infraestructura entre demos.

Leer siempre `docs/PROJECT_CONTEXT.md` y `docs/CONTRACTS.md`. Las rutas de esta ficha son propuestas del repositorio; B00 las establece.

**Zona de trabajo:** infra/environments/demo/, scripts/demo_*, Makefile, CI build y tests/deployment/.

**Fuera de alcance:** Backend remoto obligatorio, entornos siempre encendidos y restaurar sesiones antiguas por defecto.

## B08.1 — Completar infraestructura de aplicación

**Modo:** LOCAL + AZURE. **Depende de:** B06.4, B07.4.

**Implementar:** Modelar API/web, MCP interno, Job/cola, PostgreSQL, Storage, KV, UAMIs, logs acotados y modelo configurable. Desplegar imágenes por digest. Tratar endpoints y redirect URIs dinámicos sin dependencias circulares.

**Entregable:** Terraform completo, outputs mínimos y run manifest por entorno.

**Aceptación:** El plan no incluye servicios fuera del presupuesto/alcance y se despliega la app real. Readiness y diagnósticos explican un fallo de configuración.

**Entrega al siguiente agente:** `docs/handoffs/B08.1.md`, usando la plantilla común.

## B08.2 — Orquestar demo-up y seed cloud

**Modo:** AZURE. **Depende de:** B08.1.

**Implementar:** Crear preflight, apply, inicialización SQL con identidad separada, migraciones del SDK/negocio, seed y smoke. Aplicar nuevos principal IDs y URLs; reintentar propagación con límites. No dejar privilegios de inicialización en runtime.

**Entregable:** make demo-up y manifiesto de versiones/identidades sin secretos.

**Aceptación:** Desde vacío hay login, datos y recorrido disponible. Seed doble no duplica, y un fallo deja state y pasos de recuperación claros.

**Entrega al siguiente agente:** `docs/handoffs/B08.2.md`, usando la plantilla común.

## B08.3 — Implementar reset, export y retirada

**Modo:** LOCAL + AZURE. **Depende de:** B08.2.

**Implementar:** Añadir demo-reset acotado y export de resultados seleccionados. demo-down cierra admisión, drena/cancela, destruye por state y verifica Azure/Entra del proyecto. Manejar KV retenido/nombre único. No borrar state si quedan recursos.

**Entregable:** Comandos de ciclo de vida y verificador de residuos.

**Aceptación:** Tras teardown no quedan workloads del entorno; objetos retenidos/fallos se enumeran. Reset de un entorno ajeno se rechaza y export no filtra secretos.

**Entrega al siguiente agente:** `docs/handoffs/B08.3.md`, usando la plantilla común.

## B08.4 — Repetir el ciclo y registrar coste

**Modo:** AZURE. **Depende de:** B08.3.

**Implementar:** Ejecutar dos despliegues completos con environment_id distinto; comparar hashes, conteos, roles y resultados deterministas. Registrar tiempos y consumo disponible, diferenciando retraso de facturación y coste estimado.

**Entregable:** Informe de reproducibilidad y presupuesto por demo medido.

**Aceptación:** La segunda demo funciona con identidades nuevas; no depende de restos de la primera. Se conserva una lista explícita de recursos y costes residuales si los hay.

**Entrega al siguiente agente:** `docs/handoffs/B08.4.md`, usando la plantilla común.

## Puerta de salida del bloque

Dos ciclos desde cero de demo-up, prueba funcional y demo-down finalizan con los mismos fixtures y sin workloads activos propios.

Revisar las cuatro entregas, integración y contratos modificados. Una dependencia externa pendiente se informa como tal; no se sustituye por un mock para declarar este bloque completo.
